# A1 — 生成用户画像

## 基本信息

| 项目 | 说明 |
|------|------|
| 方法 | `POST` |
| 路径 | `/api/profile/analyze` |
| 功能 | 接收用户基础健康信息，自动生成用户标签与饮水目标，写入 `user_profile` 表并返回完整画像 |
| 鉴权 | 无（本模块暂不接入鉴权，由成员3 后续统一处理） |

> **BMI** 字段由数据库自动计算（`GENERATED ALWAYS AS (weight_kg / ((height_cm/100)^2)) STORED`），INSERT 时无需传入，读回即可获取。

---

## 请求参数

### Request Body（JSON）

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|------|------|------|------|----------|
| user_id | int | ✅ 是 | 用户编号 | > 0，必须在 `user_account` 表中存在 |
| age | int | ✅ 是 | 年龄 | 10 ~ 100 |
| gender | string | ✅ 是 | 性别 | `male` / `female` / `other` |
| height_cm | float | ✅ 是 | 身高（厘米） | 100 ~ 250 |
| weight_kg | float | ✅ 是 | 体重（公斤） | 20 ~ 300 |
| activity_level | string | ✅ 是 | 日常运动水平 | `low` / `medium` / `high` |
| goal | string | ✅ 是 | 健康目标 | `lose_fat` / `maintain` / `gain_muscle` |
| avg_sleep_hours | float | ✅ 是 | 平均睡眠时长（小时） | 0 ~ 24 |

### 请求示例

```json
{
  "user_id": 1,
  "age": 22,
  "gender": "male",
  "height_cm": 175,
  "weight_kg": 70,
  "activity_level": "low",
  "avg_sleep_hours": 6.5,
  "goal": "lose_fat"
}
```

## 响应参数

### 成功响应（code = 0）

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 0 = 成功 |
| msg | string | 提示信息，固定 `"ok"` |
| data | object | 画像数据 |
| data.user_id | int | 用户编号 |
| data.age | int | 年龄 |
| data.gender | string | `male` / `female` / `other` |
| data.height_cm | float | 身高（厘米） |
| data.weight_kg | float | 体重（公斤） |
| data.bmi | float | **数据库自动计算**，保留两位小数 |
| data.goal | string | `lose_fat` / `maintain` / `gain_muscle` |
| data.activity_level | string | `low` / `medium` / `high` |
| data.avg_sleep_hours | float | 平均睡眠时长（小时） |
| data.profile_tag | string | 系统自动生成的中文标签 |
| data.water_target_ml | int | 每日饮水目标（毫升），系统自动计算 |
| data.created_at | string | 创建时间 `YYYY-MM-DD HH:MM:SS` |
| data.updated_at | string | 更新时间 `YYYY-MM-DD HH:MM:SS` |

### 成功响应示例

```json

  "msg": "用户画像已存在，请更新",
  "data": null
}
```

**用户账号不存在：**
```json

  "code": 1003,
```

## 业务逻辑

```
1. 参数校验（范围 + 枚举）
2. 检查 user_account 中 user_id 是否存在 → 不存在返回 1003
3. 检查 user_profile 中 user_id 是否已有画像 → 已有返回 1001
4. 根据 (goal, activity_level) 查标签规则表 → profile_tag
5. 根据 (height_cm, weight_kg, goal) 计算饮水目标 → water_target_ml
6. INSERT INTO user_profile（不需要传 bmi，数据库自动计算）
7. SELECT 读回完整画像（获取数据库生成的 bmi、created_at、updated_at）
8. 返回成功
```

## 标签规则（TAG_RULES）

| goal | activity_level | profile_tag |
|------|---------------|-------------|
| `lose_fat` | `low` | 夏季减脂型 |
| `lose_fat` | `medium` | 夏季减脂型 |
| `lose_fat` | `high` | 夏季减脂活跃型 |
| `gain_muscle` | `low` | 夏季增肌型 |
| `gain_muscle` | `medium` | 夏季增肌型 |
| `gain_muscle` | `high` | 夏季增肌活跃型 |
| `maintain` | `low` | 夏季养生型 |
| `maintain` | `medium` | 规律养生型 |
| `maintain` | `high` | 夏季活力型 |

---

## 饮水目标计算公式

```text
标准体重 = 22 × (身高_m)²
基础饮水 = 2000ml

if 实际体重 > 标准体重:
    基础饮水 += (实际体重 - 标准体重) // 10 × 200

if goal == "lose_fat":
    基础饮水 += 200       # 减脂需额外补水

基础饮水 += 300           # 夏季高温加成

最终结果夹在 [500, 6000] 范围内
```

## 数据来源

| 步骤 | 数据源 |
|------|--------|
| 校验账号 | `user_account` 表 |
| 校验画像 | `user_profile` 表 |
| 写入画像 | `INSERT INTO user_profile` |
| 读回结果 | `user_profile`（bmi 由数据库自动生成） |

---

## 边界情况

| 场景 | 处理 |
|------|------|
| user_id 不在 user_account 中 | 返回 1003 |
| 该用户已有画像 | 返回 1001，引导使用 PUT |
| 参数超出范围 | 返回 1002，具体指出哪个字段不合法 |
| 极端身高/体重组合 | BMI 由数据库计算，始终正确 |

---

## 错误码

| code | msg | 触发条件 |
|------|-----|----------|
| 0 | ok | 成功 |
| 1001 | 用户画像已存在，请更新 | `user_profile` 中已有该 user_id |
| 1002 | 参数校验失败：{具体字段} | 字段范围或枚举值不合法 |
| 1003 | 用户账号不存在，请先注册 | `user_account` 中无该 user_id |
