# B1 — 每日健康报告

## 基本信息

| 项目 | 说明 |
|------|------|
| 方法 | `GET` |
| 路径 | `/api/report/{user_id}/daily` |
| 功能 | 生成指定日期的个人健康报告，包含健康指数、各维度拆解（饮水/运动/饮食/睡眠） |
| 鉴权 | 无 |

> **核心数据源**：成员2 已建好的视图 `v_dashboard_daily`——健康指数和各维度数据均已预计算，本接口只需 JOIN `user_profile` 获取标签和目标值即可。

---

## 请求参数

| 字段 | 类型 | 必填 | 位置 | 说明 |
|------|------|------|------|------|
| user_id | int | ✅ 是 | Path | 用户编号 |
| date | string | ✅ 是 | Query | 报告日期，格式 `YYYY-MM-DD` |

### 请求示例

```text
GET /api/report/1/daily?date=2026-07-17
```

---

## 健康指数公式（来自 `v_dashboard_daily`）

```text
health_score =
    min(实际饮水 / 饮水目标, 1.0) × 30
  + min(实际运动分钟 / 30, 1.0)     × 25
  + (饮食健康评分 / 100)            × 25
  + (睡眠质量评分 / 100)            × 20

结果四舍五入保留 2 位小数，范围 0~100
```

> **不需要在 Python 里重算。** 数据库视图 `v_dashboard_daily` 已经算好了 `health_score`。

---

## 等级评定（grade）

| 分数范围 | 等级 |
|----------|------|
| ≥ 90 | 优秀 |
| 80 ~ 89 | 良好 |
| 60 ~ 79 | 一般 |
| < 60 | 需改善 |

---

## 业务逻辑

```
1. 查 user_profile 获取 profile_tag 和 water_target_ml
   → 不存在返回 1001
2. 查 v_dashboard_daily 获取当日各维度数据 + health_score
   → 不存在（当日无任何记录）：所有值返回 0，health_score = 0，grade = "需改善"
3. 组装 breakdown，计算 completion 百分比
4. 返回
```

### SQL

```sql
-- Step 1：画像
SELECT user_id, profile_tag, water_target_ml
FROM user_profile WHERE user_id = ?;

-- Step 2：当日健康数据
SELECT stat_date, health_score, water_ml, sport_duration_min,
       food_health_score, sleep_hours, sleep_quality_score
FROM v_dashboard_daily
WHERE user_id = ? AND stat_date = ?;
```

---

## 边界情况

| 场景 | 处理 |
|------|------|
| 画像不存在 | 返回 1001 |
| 当日无任何记录（饮水/运动/饮食/睡眠都无） | `v_dashboard_daily` 查不到该天 → health_score=0, grade="需改善"，各维度 actual=0 |
| 完成度超过 100%（如饮水超标） | `completion` 上限 100%，用 `min(value, 100)` 截断 |
| date 格式错误 | 返回 1002 |

---

## 错误码

| code | msg | 触发条件 |
|------|-----|----------|
| 0 | ok | 成功 |
| 1001 | 用户画像不存在，请先创建画像 | 画像不存在 |
| 1002 | 参数校验失败：日期格式应为 YYYY-MM-DD | date 格式不合法 |
