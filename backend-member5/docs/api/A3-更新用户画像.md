# A3 — 更新用户画像

## 基本信息

| 项目 | 说明 |
|------|------|
| 方法 | `PUT` |
| 路径 | `/api/profile/{user_id}` |
| 功能 | 部分更新用户画像。当 goal / activity_level 变化时自动重算标签；当体重/身高/goal 变化时自动重算饮水目标。BMI 由数据库触发器自动重算 |
| 鉴权 | 无 |

---

## 请求参数

### Path

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| user_id | int | ✅ 是 | 用户编号 |

### Request Body（JSON，所有字段均可选，传哪个更新哪个）

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|----------|
| age | int | 否 | 10 ~ 100 |
| gender | string | 否 | `male` / `female` / `other` |
| height_cm | float | 否 | 100 ~ 250 |
| weight_kg | float | 否 | 20 ~ 300 |
| activity_level | string | 否 | `low` / `medium` / `high` |
| goal | string | 否 | `lose_fat` / `maintain` / `gain_muscle` |
| avg_sleep_hours | float | 否 | 0 ~ 24 |

### 请求示例

**只更新体重：**
```text
PUT /api/profile/1
```
```json
{
  "weight_kg": 68.0
}
```

**同时更新目标和运动水平：**
```json
{
  "goal": "gain_muscle",
  "activity_level": "medium"
}
```

---

## 响应参数

返回更新后的完整画像，字段结构**完全同 A2**，此处不再重复列出。关键点：

| 自动重算项 | 触发条件 |
|-----------|----------|
| `bmi` | weight_kg 或 height_cm 变化（数据库自动） |
| `profile_tag` | goal 或 activity_level 变化（Python 端查 TAG_RULES） |
| `water_target_ml` | weight_kg / height_cm / goal 变化（Python 端调用饮水公式） |
| `updated_at` | 任意字段变化（数据库触发器自动更新） |

### 成功响应示例

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "user_id": 1,
    "nickname": "张同学",
    "age": 22,
    "gender": "male",
    "height_cm": 175.0,
    "weight_kg": 68.0,
    "bmi": 22.20,
    "goal": "lose_fat",
    "activity_level": "low",
    "avg_sleep_hours": 6.5,
    "profile_tag": "夏季减脂型",
    "water_target_ml": 2200,
    "created_at": "2026-07-11 08:00:00",
    "updated_at": "2026-07-17 16:30:00"
  }
}
```

### 错误响应示例

**画像不存在：**
```json
{
  "code": 1001,
  "msg": "用户画像不存在，请先创建画像",
  "data": null
}
```

**参数校验失败：**
```json
{
  "code": 1002,
  "msg": "参数校验失败：weight_kg 必须在 20~300 之间",
  "data": null
}
```

---

## 业务逻辑

```
1. 检查画像是否存在 → 不存在返回 1001
2. 参数校验（只校验传入的非 null 字段）
3. 如果没有字段实际变化 → 直接返回当前画像（不写库）
4. 合并字段（传了就用新值，没传保留旧值）
5. 如果 goal 或 activity_level 变化 → 重新查 TAG_RULES → 更新 profile_tag
6. 如果 weight_kg / height_cm / goal 变化 → 重新计算 water_target_ml
7. UPDATE user_profile（BMI 由数据库自动重算，updated_at 由触发器更新）
8. SELECT 读回完整画像 → 返回
```

---

## 数据来源

| 步骤 | 数据源 |
|------|--------|
| 查当前画像 | `user_profile` JOIN `user_account` |
| 更新 | `UPDATE user_profile` |
| 读回 | 同 A2 的 JOIN 查询 |

---

## 边界情况

| 场景 | 处理 |
|------|------|
| 所有字段都传了，但值无变化 | 不写库，直接返回当前数据 |
| 只传了与标签/饮水无关的字段（如 avg_sleep_hours） | 不重算标签和饮水，只更新该字段 |
| goal + activity_level 同时变化 | 重算标签 |
| weight_kg 变化 | 数据库自动重算 BMI，Python 端重算饮水目标 |
| ⚠️ 体重更新但无体重日志表 | 当前 `user_profile` 只存最新体重，如需历史趋势后续建 `weight_log` 表 |

---

## 错误码

| code | msg | 触发条件 |
|------|-----|----------|
| 0 | ok | 成功 |
| 1001 | 用户画像不存在，请先创建画像 | 画像不存在 |
| 1002 | 参数校验失败：{具体字段} | 字段范围或枚举不合法 |
