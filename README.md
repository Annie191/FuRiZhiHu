# 伏日智护 Web App 项目需求文档

## 一、项目简介

### 1.1 项目名称

**伏日智护（FuCare）**

### 1.2 项目定位

伏日智护是一款面向夏季高温天气场景的健康管理 Web App，主要服务于需要进行日常养生、饮食管理、运动调节和作息优化的用户。系统结合用户基础信息、生活习惯与天气环境数据，为用户提供个性化的健康建议和每日计划。

### 1.3 项目目标

- 为用户提供夏季高温环境下的健康管理方案
- 帮助用户建立科学的饮食、运动、饮水和睡眠习惯
- 通过数据记录与分析提升用户健康意识
- 构建一个轻量、实用、可持续使用的个人健康管理平台

### 1.4 目标用户

- 夏季容易中暑或受高温影响的人群
- 有减脂、增肌、保持健康等管理需求的用户
- 希望规律作息、改善生活习惯的大学生与上班族

## 二、功能架构

系统整体功能结构如下：

```text
伏日智护 Web App
├─ 智能首页 Dashboard
├─ 用户健康画像
├─ 每日养生计划
├─ 饮食管理
├─ 运动管理
├─ 睡眠管理
├─ 天气与环境分析
└─ 健康社区（可选加分模块）
```

## 三、核心功能需求

### 3.1 智能首页 Dashboard

智能首页是用户进入系统后的第一页面，核心目标是让用户快速了解“今天应该如何养生”。

#### 功能内容

- 展示用户问候语与健康概览
- 展示今日健康指数
- 展示今日天气与环境风险
- 展示饮水、运动、饮食、睡眠等任务完成情况
- 展示系统自动生成的每日健康建议

#### 页面示例

```text
上午好，张同学

今日健康指数：86 分
环境状态：温度 36℃，湿度 75%，中暑风险较高

今日建议：
1. 饮水目标 2200ml
2. 建议 18:00 后进行轻度运动
3. 饮食以清淡为主，减少辛辣油腻

今日完成情况：
- 饮水 70%
- 运动 100%
- 睡眠 80%
```

#### 健康评分模型

系统可采用简单加权评分方式：

```text
健康指数 =
饮水完成度 × 30%
+ 运动完成度 × 25%
+ 饮食健康度 × 25%
+ 睡眠质量 × 20%
```

示例：

```text
score = water * 0.3 + sport * 0.25 + food * 0.25 + sleep * 0.2
```

### 3.2 用户健康画像

用户首次进入系统时填写基础健康信息，系统根据输入生成用户健康画像和标签，用于后续个性化推荐。

#### 采集信息

- 年龄
- 性别
- 身高
- 体重
- 日常运动水平
- 平均睡眠时长
- 健康目标

#### 运动水平示例

- 很少运动
- 每天约 30 分钟
- 每天 1 小时以上

#### 健康目标示例

- 减脂
- 保持健康
- 增肌

#### 画像生成示例

输入：

- 年龄：22 岁
- 体重：70kg
- 运动量：较少
- 目标：减脂

输出：

- 用户标签：夏季减脂型用户
- 推荐特点：低脂饮食、适度有氧、注意补水

### 3.3 每日养生计划

系统根据用户画像、天气情况和行为习惯，自动生成当日养生计划。

#### 功能内容

- 自动生成早餐、午间、运动、晚间等建议
- 根据天气调整户外活动强度
- 根据健康目标调整饮食与运动方向
- 根据睡眠情况动态调整当日建议

#### 示例

```text
2026-07-17 三伏养生计划

早餐：鸡蛋 + 牛奶 + 玉米
上午：饮水 500ml
下午：快走 30 分钟
晚上：23:30 前入睡
```

#### 推荐规则示例

```text
IF 温度 > 35℃
THEN 减少高强度户外运动

IF goal = 减脂
THEN 推荐低热量饮食

IF sleep < 6 小时
THEN 降低运动强度并增加休息建议
```

### 3.4 饮食管理

饮食管理模块用于记录每日饮食情况，并对营养摄入进行分析。

#### 功能内容

- 查看食物库信息
- 记录每日早餐、午餐、晚餐
- 统计热量、蛋白质、水分等摄入情况
- 生成饮食评价与优化建议

#### 食物库示例

| 食物名称 | 热量 | 属性 | 适合季节 |
| --- | --- | --- | --- |
| 西瓜 | 30 kcal/100g | 清热、补水 | 夏季 |
| 鸡蛋 | 144 kcal/100g | 高蛋白 | 四季 |
| 牛奶 | 54 kcal/100ml | 补钙、补蛋白 | 四季 |

#### 饮食分析示例

```text
今日摄入：
热量：1500 kcal
蛋白质：80g
水分：1800ml

系统评价：
蛋白质摄入较充足
建议适当增加蔬菜和饮水量
```

### 3.5 运动管理

运动管理模块用于帮助用户制定运动计划并查看执行情况。

#### 功能内容

- 选择运动目标
- 自动生成每周运动计划
- 记录运动时长与类型
- 以图表方式展示运动趋势

#### 运动目标示例

- 减脂
- 保持健康
- 增强体质

#### 每周计划示例

```text
周一：快走 30min
周三：慢跑 40min
周五：瑜伽 20min
```

#### 可视化示例

```text
运动时长趋势图

50 |
40 |        *
30 |  *
20 |
10 |
   ----------------
    周一 周三 周五
```

### 3.6 睡眠管理

睡眠管理模块用于记录用户作息情况，并生成睡眠质量评价。

#### 功能内容

- 记录入睡时间
- 记录起床时间
- 记录睡眠质量
- 输出睡眠评分与改进建议

#### 示例

```text
睡眠评分：82 分

系统建议：
最近三天睡眠不足
建议 23:30 前休息，减少熬夜
```

### 3.7 天气与环境分析

该模块负责获取或模拟天气数据，并将环境变化转化为健康风险提示。

#### 功能内容

- 获取温度、湿度、紫外线、空气质量等信息
- 评估高温、中暑、暴晒等风险
- 生成对应的健康提示

#### 示例

```text
今日环境风险：高温
建议：10:00 - 16:00 尽量避免长时间户外运动
```

#### 数据模拟方案

若项目阶段暂不接入天气 API，可采用本地模拟数据：

```json
{
  "temperature": 36,
  "humidity": 70
}
```

### 3.8 健康社区（可选加分模块）

健康社区用于增强互动性，可作为拓展或加分功能。

#### 功能内容

- 发布健康动态
- 分享运动、饮食、作息成果
- 点赞互动

#### 示例

```text
用户发布：
“今天跑步 5 公里，状态很好。”

其他用户可以点赞和查看内容。
```

## 五、项目特色与亮点

- 聚焦“三伏天”和高温健康管理，主题明确，具有现实意义
- 将天气环境与个人健康数据结合，突出场景化推荐
- 功能覆盖饮食、运动、睡眠、饮水等多个维度，体系完整
- 可采用规则推荐实现核心功能，开发难度适中，适合课程项目落地
- 社区模块可作为加分项，提升系统互动性和展示效果

## 六、项目实现建议

### 6.1 开发重点

- 优先完成用户画像、智能首页、每日计划三个核心模块
- 第二阶段完善饮食、运动、睡眠记录功能
- 最后根据时间补充天气接口和社区互动模块

### 6.2 实现方式建议

- 前端：负责页面展示、表单输入、图表可视化
- 后端：负责用户数据、计划生成、记录管理
- 数据层：完成数据库表设计与基础接口联调
- 推荐逻辑：前期可使用规则判断，无需复杂 AI 模型

## 七、五人分工建议

以下分工适合 5 人课程项目协作，采用“前端 1 人 + 后端 4 人”的分工方式；如果后续有真实姓名，只需将“成员 1-5”替换即可。

| 成员 | 主要职责 | 具体任务 |
| --- | --- | --- |
| 成员 1 | 前端负责人 | 负责 React 项目搭建、路由管理、全局布局设计（导航栏、侧边栏）、首页 Dashboard、健康评分展示以及公共组件封装 |
| 成员 2 | 后端开发（数据库方向） | 负责 SQLite 数据库设计与建表，实现用户、饮食、运动、睡眠等核心数据表结构设计，完成数据库初始化、测试数据准备与数据维护 |
| 成员 3 | 后端负责人（接口方向） | 负责 Node.js + Express 后端框架搭建，实现用户注册登录、JWT 身份认证，以及饮水、饮食、运动、睡眠、健康档案等页面所需的业务接口 |
| 成员 4 | 后端开发（推荐规则方向） | 负责健康评分算法、三伏养生推荐规则、天气数据处理，以及每日健康计划和推荐逻辑实现 |
| 成员 5 | 后端开发（画像分析方向） | 负责用户画像分析、健康报告生成、数据统计接口，以及健康趋势分析等功能实现 |

## 八、总结

伏日智护项目以夏季高温健康管理为切入点，围绕“看健康状态、定养生计划、做行为记录、给个性建议”展开设计。项目主题鲜明、结构完整、难度适中，适合作为课程 Web App 设计与实现项目。

## 九、数据库成员 2 交付内容

已在项目下补充 `database` 目录，适合成员 2 直接作为数据库方向的课程项目代码提交：

- `database/01_schema.sql`：SQLite 建表脚本，包含外键、唯一约束、检查约束、索引和更新时间触发器
- `database/02_seed.sql`：测试数据脚本，方便前端展示和后端接口联调
- `database/03_views_and_queries.sql`：首页统计视图、健康分汇总视图和常用查询示例
- `database/init_sqlite.py`：使用 Python 标准库一键生成本地 `SQLite` 数据库文件
- `database/README.md`：数据库设计说明与执行顺序

本次数据库实现除了需求文档中建议的 `user_profile`、`food_library`、`food_record`、`sport_record`、`sleep_record`、`post` 相关表外，还补充了项目真正落地时必需的：

- `user_account`：作为所有业务表的统一用户主表
- `water_record`：支撑首页“饮水完成度”与饮水管理
- `weather_daily`：支撑天气与环境分析模块
- `daily_plan`：支撑每日养生计划生成与展示

如果后续成员 3、4、5 继续开发后端接口和推荐逻辑，可以直接基于这套 SQLite 表结构联调。
